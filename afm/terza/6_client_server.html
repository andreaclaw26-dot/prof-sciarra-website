02

La teoria, per bene

CLIENT, SERVER, PROTOCOLLI E CONDIVISIONE

Il termine client-server indica un'architettura di rete nella quale un computer client si connette a un server per usare un certo servizio, appoggiandosi alla sottostante architettura protocollare. È un'evoluzione della condivisione semplice: la presenza di un server lascia che sia lui a gestire gli accessi.

CLIENT

Chi chiede: il tuo PC, il telefono, la console, il browser. Invia una richiesta e usa il servizio che riceve.

SERVER

Chi offre e governa: un computer sempre acceso che condivide risorse (file, partite, video) e gestisce gli accessi: permessi, code, sicurezza.

PROTOCOLLO

Il linguaggio comune di regole con cui client e server si parlano: HTTP per il web, TCP/IP per il trasporto.

RICHIESTA / RISPOSTA

Il cuore del modello: il client invia una request, il server risponde con una response e un codice: 200 OK, 404 non trovato…

03

I problemi dello streaming

INPUT LAG E QUALITÀ VIDEO: PROVALI NEL LABORATORIO

🐌 Input lag

Nel cloud gaming il tuo comando fa un viaggio enorme: input → server (latenza), il server calcola e disegna il frame, poi video → schermo (altra latenza). Il ritardo che senti è circa il doppio del ping, più la codifica.

CALCOLA IL TUO RITARDO CON LA LATENZA ATTUALE
input → server: 60 ms+codifica: 30 ms+video → schermo: 60 ms
= 150 ms

Qualità video bassa

Per viaggiare nella tua banda, il video viene compresso. Se la banda è poca, il server abbassa la qualità (fino a 144p!) oppure il buffer si svuota e parte il buffering.

🧪 Provalo: nel laboratorio porta la banda a 2 Mbps e guarda TubeStream passare a 144p e singhiozzare. Poi riportala a 100 e respira.
⚠ Ricorda: senza rete, il client è un soprammobile. Tutti i tuoi "file nel cloud" esistono solo finché il server risponde.
