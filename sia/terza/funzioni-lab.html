LE FUNZIONI
istruzioni che diventano mattoni

Una funzione è una scatola con un nome: le dai dei dati in ingresso, fa un lavoro e ti restituisce un risultato. La scrivi una volta e la usi quante volte vuoi.

Dalla firma al valore di ritorno, dallo scope delle variabili al passaggio per valore/riferimento: guarda lo stack delle chiamate riempirsi e svuotarsi mentre il codice esegue.

Che cos'è una funzione? (idea generale, prima di Java)

Una funzione è un blocco di istruzioni con un nome, che riceve dei dati, li elabora e produce un risultato. Esiste in ogni linguaggio: si chiama funzione, metodo, procedura o sottoprogramma.

📥Input

I parametri (o argomenti) sono i dati che consegni alla funzione quando la chiami. Possono essere zero, uno o tanti.

area(3, 5) → due input

⚙️Elaborazione

Il corpo è la sequenza di istruzioni che fa il lavoro. Sta tutto racchiuso tra parentesi graffe e ha le sue variabili private.

base * altezza

📤Output

Il valore di ritorno è il risultato che torna al punto della chiamata. Se non serve alcun risultato la funzione è void.

return 15;

🧠Teoria lampo

Pensa a una macchina del caffè: metti dentro monete e una capsula (input), la macchina fa il suo lavoro (elaborazione) e ti dà il caffè (output). Non ti serve sapere come funziona il boiler interno: ti basta conoscere come si usa.

💡 In una frase

Funzione = nome + dati in ingresso + lavoro + risultato in uscita.

A cosa serve?

  • Riuso: scrivi il codice una volta, lo chiami mille volte.
  • Ordine: un problema grande si spezza in problemi piccoli (decomposizione).
  • Nomi che parlano: calcolaSconto() si capisce meglio di 8 righe di calcoli.

Una funzione è un'astrazione procedurale: nasconde come un'operazione è realizzata ed espone solo che cosa fa, attraverso la sua interfaccia (firma: nome, parametri, tipo di ritorno).

🔑 Contratto

La firma è un contratto fra chi scrive la funzione e chi la usa: il chiamante garantisce argomenti del tipo giusto, la funzione garantisce un valore del tipo dichiarato (o un comportamento documentato).

Vantaggi concreti: riuso, manutenzione (correggi in un punto solo), leggibilità, testabilità (puoi verificare una funzione da sola), lavoro di squadra (ognuno sviluppa una funzione).

Terminologia a confronto: in Java si parla di metodi (funzioni dentro una classe); in C sono funzioni; in Python def; in pseudocodice procedura (senza valore di ritorno) e funzione (con valore di ritorno).

Una funzione è un'astrazione procedurale con un record di attivazione (frame) allocato sullo stack a ogni chiamata: contiene parametri, variabili locali, indirizzo di ritorno e riferimento al frame chiamante. Questo modello spiega scope, ricorsione e StackOverflowError.

🔑 Funzione pura

Una funzione è pura se, a parità di argomenti, restituisce sempre lo stesso valore e non modifica stato esterno (nessun effetto collaterale). Le funzioni pure sono prevedibili, testabili, parallelizzabili e memoizzabili.

⚠️ Stato nascosto

Campi static modificati, input da tastiera, Random, System.currentTimeMillis() e modifiche ad array/oggetti ricevuti rendono la funzione impura: stessa chiamata → risultati diversi.

Complessità: una funzione che contiene un ciclo su n elementi è O(n); se chiama sé stessa due volte (Fibonacci ingenuo) diventa O(2ⁿ); la ricorsione lineare (fattoriale) resta O(n) ma con costo di stack O(n).

04

      

        
return, void e vie d'uscita

        
Il return fa due cose: restituisce un valore e termina subito la funzione. Ogni percorso del codice deve essere coerente, altrimenti il compilatore si rifiuta.

      

      

        
        
      

    


    

      
↩️return con valore

        
La funzione ha un tipo di ritorno (int, double, boolean, String…). Ogni percorso deve terminare con un return di quel tipo.

        
static int quadrato(int n) {    return n * n;}

      
🈳void

        
La funzione fa qualcosa (stampa, modifica un oggetto) ma non restituisce niente. Il return; senza valore è permesso per uscire in anticipo.

        
static void saluta(String n) {    if (n.isEmpty()) return;    System.out.println(n);}

      
🚪Uscita anticipata

        
Più return nella stessa funzione sono leciti: il primo che viene eseguito chiude la funzione. Utile per i casi eccezionali.

        
static int dividi(int a, int b) {    if (b == 0) return 0;    return a / b;}

Parametri: passaggio per valore e per riferimento

        
In Java tutto passa per valore: per i tipi primitivi si copia il dato, per gli oggetti si copia il riferimento. Guarda la memoria.

      

      

        
        
      

    


    

      
🔢Parametro formale vs argomento

        
Nella definizione scrivi i parametri formali (int x): sono segnaposto. Nella chiamata passi gli argomenti (doppio(5)): sono i valori veri.

        
static int doppio(int x) { … }   // x = parametro formaleint r = doppio(5);               // 5 = argomentoint r2 = doppio(r);              // argomento calcolato

        
🔢 Ordine e numero
Gli argomenti sono assegnati ai parametri in ordine e devono essere tanti quanti i parametri e di tipo compatibile: area(b, h) ≠ area(h, b) se i valori differiscono!

      

      
🔗Le due situazioni

        
Primitivi (int, double, char, boolean)
La funzione riceve una copia. Quello che fa al parametro non cambia la variabile del chiamante. Per questo scambia(a,b) con due int non funziona.

        
Oggetti e array
La funzione riceve una copia del riferimento: due telecomandi per lo stesso oggetto. Modificare gli elementi dell'array (v[0] = 9) è visibile al chiamante; riassegnare il parametro (v = new int[3]) no.

        
⚠️ String e wrapper
String, Integer, Double sono immutabili: anche se passi un riferimento, ogni "modifica" crea un nuovo oggetto → si comportano come i primitivi.

Ricorsione: una funzione che chiama sé stessa

        
Due ingredienti obbligatori: il caso base (si ferma) e il passo ricorsivo (si avvicina al caso base). Guarda l'albero delle chiamate crescere e poi «richiudersi».

      

      

        
        
      

    


    

      

        
🧠Come ragiona

        
La ricorsione è come chiedere aiuto a un compagno più piccolo: «non so fare 5!, ma so che è 5 × 4!. Chiedo a te di calcolare 4!». E lui fa lo stesso, finché qualcuno arriva al caso semplice (1! = 1) e la risposta risale la catena.

          
💡 Regola
Serve sempre un caso base che non richiama nessuno, altrimenti la catena non finisce mai.

        
Ogni chiamata apre un frame nuovo sullo stack con i propri parametri: fatt(5) attende fatt(4), che attende fatt(3)… Quando il caso base restituisce, i valori risalgono e ogni frame può completare il proprio calcolo.

          
Javaschema ricorsivo


static int fatt(int n) {
    if (n <= 1) return 1;        // 1. CASO BASE
    return n * fatt(n - 1);      // 2. PASSO RICORSIVO
}

          
📐 Due fasi
Discesa: le chiamate si impilano fino al caso base. Risalita: i valori di ritorno si combinano fino alla prima chiamata.

        
La ricorsione lineare (una sola chiamata ricorsiva per frame) ha complessità O(n) e profondità di stack O(n). La ricorsione multipla (Fibonacci ingenuo) genera un albero con O(2ⁿ) chiamate: enormemente inefficiente, ma si risolve con la memoizzazione o con l'approccio iterativo.

          
⚠️ Stack overflow
Lo stack ha dimensione limitata (in JVM ~512 KB-1 MB): ricorsione troppo profonda → java.lang.StackOverflowError. La tail recursion (chiamata ricorsiva come ultima operazione) in Java non è ottimizzata dal compilatore: meglio un ciclo.

          
🔢 Chiamate di fib(n)
chiamate(n) = 1 + chiamate(n−1) + chiamate(n−2) → fib(5) = 15 chiamate, fib(20) = 21 891, fib(30) ≈ 2,7 milioni.

📏Le regole

        
✅ Cosa DEVE cambiare
Il numero dei parametri, il loro tipo o il loro ordine. Tutto qui: questa combinazione è la firma del metodo.

        
⛔ Cosa NON basta
Cambiare solo il tipo di ritorno o solo il nome dei parametri → method stampa(int) is already defined. La firma non comprende il tipo di ritorno!

        
🎯 Risoluzione della chiamata
Il compilatore sceglie il metodo più specifico compatibile con gli argomenti, a tempo di compilazione (static dispatch). Con stampa(5) vince stampa(int) su stampa(double).

        
⚠️ Ambiguità
stampa(null) con stampa(String) e stampa(int[]) → errore reference to stampa is ambiguous: serve un cast esplicito.

📚Glossario

        
funzione / metodo
Blocco di codice nominato che esegue un compito; in Java è sempre dentro una classe → si chiama metodo.

        
firma (signature)
Nome del metodo + numero, tipo e ordine dei parametri. È ciò che identifica univocamente un metodo (il tipo di ritorno non ne fa parte).

        
parametro formale / argomento
Il segnaposto nella definizione (int x) vs il valore passato nella chiamata (doppio(5)).

        
tipo di ritorno
Il tipo del valore prodotto; void se non viene restituito nulla.

        
valore di ritorno
Il risultato consegnato al punto della chiamata tramite return.

        
scope / visibilità
La porzione di codice in cui una variabile esiste e può essere usata.

        
frame / record di attivazione
L'area di stack creata a ogni chiamata: parametri, variabili locali, indirizzo di ritorno.

        
call stack
La pila dei frame attivi; l'ultimo entrato è il primo a uscire (LIFO).

        
passaggio per valore / per riferimento
Copia del dato (primitivi) vs copia del riferimento (oggetti e array).

        
effetto collaterale (side effect)
Qualsiasi modifica di stato esterno alla funzione: campi static, oggetti ricevuti, output a video.

        
overload
Più metodi con lo stesso nome e firme diverse nella stessa classe.

        
ricorsione · caso base · passo ricorsivo
Funzione che chiama sé stessa; il caso base termina, il passo ricorsivo riduce il problema.

        
StackOverflowError
Errore a run-time: stack esaurito per ricorsione troppo profonda o senza caso base.

        
memoizzazione
Memorizzare i risultati già calcolati per evitare chiamate ricorsive ripetute (fib: da O(2ⁿ) a O(n)).

        
API / libreria
Insieme di funzioni già pronte (Math, Arrays, Scanner): si usa l'interfaccia senza conoscere l'implementazione.
