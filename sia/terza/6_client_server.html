02

La teoria, per bene

CLIENT, SERVER, PROTOCOLLI E CONDIVISIONE

Il termine client-server indica un'architettura di rete nella quale un computer client (o terminale) si connette a un server per usare un certo servizio — ad esempio la condivisione di una risorsa hardware o software con altri client — appoggiandosi alla sottostante architettura protocollare. I sistemi client/server sono un'evoluzione della condivisione semplice delle risorse: la presenza di un server permette a più client di condividere le risorse, lasciando che sia il server a gestire gli accessi.

CLIENT

Chi chiede: il tuo PC, il telefono, la console, il browser. Invia una richiesta e usa il servizio che riceve.

SERVER

Chi offre e governa: un computer sempre acceso che condivide risorse (file, partite, video, giochi) e gestisce gli accessi: permessi, code, sicurezza.

PROTOCOLLO

Il linguaggio comune di regole con cui client e server si parlano: HTTP per il web, TCP/IP per il trasporto. Senza protocollo, niente comprensione.

RICHIESTA / RISPOSTA

Il cuore del modello: il client invia una request, il server risponde con una response e un codice: 200 OK, 404 non trovato… (ti ricordi l'errore 404?).

Prima: ogni computer parla con ogni altro (6 collegamenti su 4 PC). Nessuno controlla permessi, code o sicurezza: è il caos delle origini.
03

Cenni storici: da un mainframe al cloud

SEI TAPPE PER CAPIRE DA DOVE VIENE TUTTO QUESTO
1960s–1969
MAINFRAME + TERMINALI · ARPANET

Grandi computer centrali (mainframe) servono terminali "stupidi" senza cervello proprio: è l'antenato del modello client-server. Nel 1969 ARPANET collega quattro università americane: nasce l'idea di rete.

1980s
PC E RETI LOCALI (LAN)

I personal computer entrano negli uffici e nelle scuole. Nascono i file server e i print server: condividere stampanti e cartelle diventa normale, e il modello client-server si standardizza.

1991
WORLD WIDE WEB

Il browser (client) chiede pagine, i web server rispondono con il protocollo HTTP: la coppia client-server più famosa della storia, ancora oggi alla base di internet.

2005–2006
STREAMING E CLOUD

Nasce YouTube (2005) e AWS (2006): i data center diventano gli "hard disk del mondo". Guardare mentre si scarica diventa un'abitudine di massa.

2012
GOOGLE DRIVE

L'hard disk virtuale: i tuoi documenti, foto e video vivono sui server di Google e li raggiungi da qualsiasi dispositivo. Il "posto" dei tuoi file non è più casa tua.

2010 → OGGI
CLOUD GAMING

Da OnLive e Gaikai fino a Xbox Game Pass e GeForce Now: il videogioco gira su server remoti e arriva a casa tua come un flusso video, tipo Netflix ma interattivo.

Gli esempi di ogni giorno

LI USI GIÀ TUTTI: ORA LI RICONOSCI

☁️ Google Drive

Un hard disk virtuale che sta sui server di Google: apri un documento, guardi una foto o un video, ma i dati sono tutti lì, nei loro data center. Tu sei solo un client con una finestra aperta.

🎮 Hosting di una partita

Crei un server privato usando le risorse messe a disposizione dagli sviluppatori del videogioco: gli altri giocatori (client) si connettono al tuo server, che gestisce turni, accessi e stato del mondo.

📺 Streaming video

Scarichi un video che sta su un server (YouTube, per esempio) e lo guardi mentre lo stai scaricando: il buffer è la piccola scorta di video già arrivata che ti salva dai singhiozzi.

☁️ Cloud gaming

Detto anche gaming on demand o "gioco in streaming", alla Netflix: il videogioco gira su server remoti e viene trasmesso al tuo dispositivo. I tre tipi principali:

05

I problemi dello streaming

INPUT LAG E QUALITÀ VIDEO: PROVALI NEL LABORATORIO

🐌 Input lag

Nel cloud gaming il tuo comando fa un viaggio enorme: input → server (latenza), il server calcola e disegna il frame, poi video → schermo (altra latenza). Il ritardo che senti è circa il doppio del ping, più la codifica.

CALCOLA IL TUO RITARDO CON LA LATENZA ATTUALE
input → server: 60 ms+codifica: 30 ms+video → schermo: 60 ms
= 150 ms

Qualità video bassa

Per viaggiare nella tua banda, il video viene compresso. Se la banda è poca, il server abbassa la qualità (fino a 144p!) oppure il buffer si svuota e parte il buffering. Nello streaming di giochi è ancora più critico: il video deve arrivare in tempo reale, non "quando capita".

🧪 Provalo: nel laboratorio porta la banda a 2 Mbps e guarda TubeStream passare a 144p e singhiozzare. Poi riportala a 100 e respira.
⚠ Ricorda: senza rete, il client è un soprammobile. Tutti i tuoi "file nel cloud" esistono solo finché il server risponde.

In breve: tre regole d'oro

1

Chi chiede, chi offre

Il client richiede un servizio, il server lo offre e gestisce gli accessi alle risorse condivise: permessi, code, sicurezza. Tutto si appoggia ai protocolli.

2

È un'evoluzione della condivisione

Prima ogni PC condivideva con ogni PC (caos); con il server c'è un regista unico che ordina gli accessi. Meno collegamenti, più controllo.

3

Il cloud ha un prezzo fisico

Drive, streaming e cloud gaming vivono su server reali: latenza (input lag) e banda (qualità video) sono il conto che paghi ogni volta che clicchi.
