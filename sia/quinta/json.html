📘 JSON: il linguaggio dei dati

Cos'è JSON?

JSON (JavaScript Object Notation) è un formato di testo leggero per lo scambio di dati. Nato all'inizio degli anni 2000, è oggi lo standard de facto per le API REST e la comunicazione tra sistemi.

💡 Curiosità: JSON è derivato dalla sintassi degli oggetti JavaScript, ma è indipendente dal linguaggio. Tutti i linguaggi moderni (Python, Java, PHP, C#, ecc.) hanno librerie per leggerlo e scriverlo.

Perché JSON è così diffuso nelle aziende?

  • Leggibilità: facile da leggere per l'uomo
  • Leggerezza: meno verboso di XML
  • Universalità: supportato da tutti i linguaggi
  • Web-friendly: nativo nei browser
  • Database NoSQL: MongoDB salva i dati in formato BSON (JSON binario)

Casi d'uso aziendali

  • 🔄 Scambio dati tra ERP e CRM
  • 🌐 API REST per e-commerce
  • ⚙️ File di configurazione (es. VSCode, package.json)
  • 📱 Comunicazione app mobile ↔ server
  • 💾 Log e backup strutturati

La sintassi JSON

JSON si basa su due strutture fondamentali:

1. L'oggetto { }

Una collezione di coppie chiave : valore, separate da virgola.

{
  "nome": "Mario Rossi",
  "eta": 30,
  "impiegato": true
}

2. L'array [ ]

Una lista ordinata di valori, separati da virgola.

["Java", "SQL", "JSON"]

I 6 tipi di valore ammessi

TipoEsempioUso
Stringa"Ciao"Testo (sempre tra doppi apici!)
Numero42, 3.14Interi o decimali
Booleanotrue / falseValori logici
NullnullValore assente
Oggetto{...}Struttura annidata
Array[...]Liste di elementi
⚠️ Regole importanti:
  • Le chiavi devono essere stringhe tra doppi apici (no singoli apici!)
  • Niente virgola dopo l'ultimo elemento (no "trailing comma")
  • Niente commenti
  • Distingue maiuscole/minuscole (case-sensitive)

📊 JSON vs altri formati

Confrontiamo JSON con altri formati comuni per lo scambio di dati:

JSON

Pro: leggero, leggibile, nativo nel web

Contro: niente commenti, no schema nativo

Uso: API REST, config, NoSQL

XML

Pro: schema (XSD), commenti, molto strutturato

Contro: verboso, pesante

Uso: SOAP, configurazioni enterprise

CSV

Pro: semplicissimo, compatto

Contro: solo dati tabellari, no gerarchie

Uso: export Excel, database

YAML

Pro: leggibilissimo, supporta commenti

Contro: sensibile agli spazi

Uso: config (Docker, Kubernetes)

Esempio: stesso dato in 3 formati

JSON:

{ "nome": "Mario", "eta": 30 }

XML:

<persona>
  <nome>Mario</nome>
  <eta>30</eta>
</persona>

CSV:

nome,eta
Mario,30

💻 JSON in JavaScript

JavaScript ha due metodi nativi per lavorare con JSON:

1. JSON.parse() - da stringa a oggetto

const testo = '{"nome":"Luigi","eta":40}';
const obj = JSON.parse(testo);
console.log(obj.nome);  // "Luigi"

2. JSON.stringify() - da oggetto a stringa

const persona = { nome: "Laura", eta: 28 };
const testo = JSON.stringify(persona);
console.log(testo);  // '{"nome":"Laura","eta":28}'
