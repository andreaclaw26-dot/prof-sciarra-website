1. L'idea di Classe: il "progetto"

Dal mondo reale al codice

Nel mondo reale esistono moltissimi oggetti individuali che sono tutti dello stesso tipo. Pensa alle automobili: possono esistere migliaia di esemplari dello stesso modello (es. una Fiat 500). Ognuno è stato costruito a partire dallo stesso progetto (il blueprint), e per questo ha gli stessi componenti e le stesse caratteristiche di base: ruote, motore, targa, colore…

Nella programmazione a oggetti usiamo la stessa idea: una Classe è il progetto da cui vengono creati i singoli oggetti. La tua automobile personale, con la sua targa e il suo colore, è un' istanza (un esemplare specifico) della classe Automobile.

🏭 La classe = il progetto

Definisce come è fatta un'automobile: quali informazioni possiede (targa, marca, prezzo…) e quali azioni può compiere (avviarsi, spegnersi, aggiornare i km…).

🚗 L'oggetto = l'esemplare

È una singola auto concreta creata dal progetto. Più oggetti possono nascere dalla stessa classe, ognuno con i propri valori, indipendenti dagli altri.

2. Anatomia della classe Automobile

Stato (campi) e comportamento (metodi)

Vediamo come il "progetto" viene scritto in Java. Una classe racchiude due cose: lo stato (i campi) e il comportamento (i metodi). 

package com.dagomari;

/*
 * Questa è la CLASSE, ovvero il "progetto".
 * Definisce come è fatta un'Automobile.
 */
public class Automobile {

    // 1. STATO (Campi)
    // Ogni auto avrà i propri valori per questi campi.
    private String targa;
    private String marca;
    private String modello;
    private int anno;
    private double chilometraggio;
    private double prezzo;
    private String carburante;
    private String cambio;
    private boolean disponibile;
    private String colore;

    // Stato operativo: di default il motore è spento.
    private boolean accesa = false;

    // 2. COSTRUTTORE
    // Costruisce un oggetto a partire dal progetto,
    // assegnando i valori iniziali ai campi.
    public Automobile(String targa, String marca, String modello, int anno,
                      double chilometraggio, double prezzo, String carburante,
                      String cambio, boolean disponibile, String colore) {
        this.targa = targa;
        this.marca = marca;
        this.modello = modello;
        this.anno = anno;
        this.chilometraggio = chilometraggio;
        this.prezzo = prezzo;
        this.carburante = carburante;
        this.cambio = cambio;
        this.disponibile = disponibile;
        this.colore = colore;
    }

    // 3. COMPORTAMENTO (Metodi)
    // Definiscono come l'oggetto interagisce col mondo
    // e come il suo stato può cambiare.
    public void avvia() {
        accesa = true;
    }

    public void spegni() {
        accesa = false;
    }

    public void aggiornaChilometraggio(double km) {
        if (km > 0) {
            chilometraggio = chilometraggio + km;
        }
    }

    public void applicaSconto(double percentuale) {
        prezzo = prezzo - (prezzo * percentuale / 100);
    }

    public void stampaStato() {
        System.out.println("--- Stato Automobile ---");
        System.out.println("Targa: " + targa);
        System.out.println("Marca: " + marca + " " + modello);
        System.out.println("Anno: " + anno);
        System.out.println("Colore: " + colore);
        System.out.println("Carburante: " + carburante + " · Cambio: " + cambio);
        System.out.println("Chilometraggio: " + chilometraggio + " km");
        System.out.println("Prezzo: " + prezzo + "€");
        System.out.println("Disponibile: " + disponibile);
        System.out.println("Accesa: " + accesa);
        System.out.println("------------------------");
    }
}

Campi

Le variabili targa, marca, modello, anno, chilometraggio, prezzo, carburante, cambio, disponibile, colore rappresentano lo stato dell'oggetto: ogni auto avrà i propri valori.

Metodi

I metodi avvia, spegni, aggiornaChilometraggio, applicaSconto e stampaStato definiscono il comportamento: sono le azioni che l'oggetto può compiere.

Il costruttore. È un metodo speciale (stesso nome della classe, senza tipo di ritorno) che viene chiamato con new. Serve a impostare lo stato iniziale dell'oggetto: senza di esso i campi resterebbero vuoti.

3. La classe è solo il progetto

Perché non c'è un main?

Avrai notato che la classe Automobile non contiene un metodo main. Questo è fondamentale: Automobile non è un'applicazione completa, è solo il progetto. La responsabilità di creare e usare gli oggetti spetta a un'altra classe dell'applicazione.

Regola pratica. Una classe "modello" (come Automobile) descrive com'è fatto qualcosa. Una classe "applicazione" (con il main) descrive cosa fa il programma.

4. Creare e usare oggetti (istanze)

La classe Main e la parola chiave new

Vediamo ora una classe che si occupa di costruire e usare le automobili definite dal nostro progetto. Contiene il metodo main, il punto di partenza del programma. 

/*
 * Questa è la classe che "usa" il progetto Automobile.
 * Contiene il metodo main, punto di partenza dell'applicazione.
 */
public class Main {
    public static void main(String[] args) {

        // 1. Creiamo due Automobili diverse dal progetto.
        //    auto1 e auto2 sono due "istanze" della classe Automobile.
        Automobile auto1 = new Automobile(
            "AB123CD", "Fiat", "500", 2021,
            32000, 12900.00, "Benzina", "Manuale",
            true, "Rosso");

        Automobile auto2 = new Automobile(
            "XY456ZW", "Tesla", "Model 3", 2023,
            8000, 39900.00, "Elettrico", "Automatico",
            true, "Bianco");

        // 2. Usiamo i metodi su auto1.
        auto1.avvia();
        auto1.aggiornaChilometraggio(150);
        auto1.stampaStato();

        // 3. Usiamo i metodi su auto2.
        auto2.avvia();
        auto2.applicaSconto(10);
        auto2.spegni();
        auto2.stampaStato();
    }
}

L'importanza di new

new Automobile(...) è ciò che costruisce l'oggetto in memoria. La prima chiamata crea auto1; la seconda crea auto2, un oggetto completamente separato dal primo.

Incapsulamento

I campi sono private: non si modificano dall'esterno con auto1.prezzo = …, ma solo tramite i metodi (es. applicaSconto). Così lo stato resta coerente.

5. Gli oggetti sono indipendenti

Lo stesso progetto, stati diversi

Eseguendo Main, l'output sarà:

--- Stato Automobile ---
Targa: AB123CD
Marca: Fiat 500
Anno: 2021
Colore: Rosso
Carburante: Benzina · Cambio: Manuale
Chilometraggio: 32150.0 km
Prezzo: 12900.0€
Disponibile: true
Accesa: true
------------------------
--- Stato Automobile ---
Targa: XY456ZW
Marca: Tesla Model 3
Anno: 2023
Colore: Bianco
Carburante: Elettrico · Cambio: Automatico
Chilometraggio: 8000.0 km
Prezzo: 35910.0€
Disponibile: true
Accesa: false
------------------------

Questo output dimostra il punto più importante: auto1 e auto2 sono istanze separate. Hanno targhe, marche, prezzi e chilometraggi diversi. Anche le modifiche allo stato operativo (come spegni()) si applicano solo all'oggetto specifico su cui è stato chiamato il metodo: auto1 resta accesa, auto2 no.
