Capitolo 01

Il problema: dati indifesi

Immaginiamo di dover gestire gli studenti di un istituto. La prima idea è quella di creare una classe con i campi accessibili a tutti.

public class Studente {
    public String nome;
    public int eta;
    public double media;
}

Chiunque, in qualsiasi punto del programma, può scrivere:

Studente s = new Studente();
s.nome  = "";        // nome vuoto? Nessuno controlla
s.eta   = -42;       // età negativa? Nessuno controlla
s.media = 99.9;      // media fuori scala? Nessuno controlla

System.out.println(s.eta);   // -42
⚠️
Il compilatore non dice nulla. Il programma compila, parte e gira… con dati assurdi dentro. L'errore non esplode subito: esploderà molto più tardi, magari nel calcolo della media di classe, e sarà difficilissimo capire da dove arriva.

Nel mondo reale — e a maggior ragione in un sistema informativo aziendale — un'anagrafica clienti con un codice fiscale vuoto o un saldo bancario negativo non autorizzato è un disastro. Serve un filtro.

Capitolo 02

La soluzione: incapsulamento

Si dichiarano i campi private e si forniscono metodi pubblici per leggerli (getter) e modificarli (setter). Quei metodi sono l'unica porta d'ingresso, e possono controllare cosa entra.

public class Studente {

    // 1. I campi sono PRIVATI: visibili solo dentro questa classe
    private String nome;
    private int eta;
    private double media;

    // 2. Costruttore che usa i setter (riusa la validazione!)
    public Studente(String nome, int eta, double media) {
        setNome(nome);
        setEta(eta);
        setMedia(media);
    }

    // 3. GETTER — legge il valore, non lo modifica
    public String getNome() {
        return nome;
    }

    // 4. SETTER — valida e poi assegna
    public void setNome(String nome) {
        if (nome == null || nome.isBlank()) {
            throw new IllegalArgumentException("Il nome non può essere vuoto");
        }
        this.nome = nome;   // "this" distingue il campo dal parametro
    }

    public int getEta() {
        return eta;
    }

    public void setEta(int eta) {
        if (eta < 0 || eta > 120) {
            throw new IllegalArgumentException("Età non valida: " + eta);
        }
        this.eta = eta;
    }

    public double getMedia() {
        return media;
    }

    public void setMedia(double media) {
        if (media < 0 || media > 10) {
            throw new IllegalArgumentException("Media non valida: " + media);
        }
        this.media = media;
    }

    @Override
    public String toString() {
        return "Studente{nome='" + nome + "', eta=" + eta + ", media=" + media + "}";
    }
}

Ora il programma esterno funziona così:

Studente s = new Studente("Mario Rossi", 17, 7.5);

System.out.println(s.getNome());   // Mario Rossi

s.setEta(18);                      // OK, 18 è valido
System.out.println(s.getEta());    // 18

s.setEta(-42);                     // ✗ Lancia IllegalArgumentException
// s.setNome("");                  // ✗ Lancia IllegalArgumentException
💡
La parola chiave this. Dentro al setter il parametro si chiama eta come il campo. Scrivendo this.eta indichiamo il campo dell'oggetto, mentre eta da solo è il parametro ricevuto.

Compilazione vs Esecuzione

Attenzione a una distinzione che confonde spesso:

  • Errore di compilazione: s.eta = 18; non compila perché eta è private. Il programma non parte nemmeno.
  • Eccezione a runtime: s.setEta(-42); compila benissimo, ma a tempo di esecuzione il setter lancia IllegalArgumentException e il programma si interrompe (a meno che non gestiamo l'eccezione con try/catch).
Capitolo 03

Convenzioni di denominazione

In Java esistono regole precise (dette JavaBeans) per nominare questi metodi. Rispettarle è fondamentale: gli strumenti di sviluppo e i framework usano queste regole per riconoscere automaticamente le proprietà di un oggetto.

Campo dichiarato Getter Setter
private String nome; public String getNome() public void setNome(String nome)
private int eta; public int getEta() public void setEta(int eta)
private double media; public double getMedia() public void setMedia(double media)
private boolean attivo; public boolean isAttivo() ⚠️ public void setAttivo(boolean attivo)
🔎
Eccezione importante: per i campi di tipo boolean il getter si chiama isXxx(), non getXxx(). Quindi isAttivo(), isMaggiorenne(), isDisponibile(). Il setter invece resta setAttivo().

Regole pratiche

Getter Caratteristiche
  • Non ha parametri
  • Restituisce il tipo del campo
  • Di solito fa solo return campo;
  • Per i boolean si chiama isXxx()
Setter Caratteristiche
  • Ha un parametro dello stesso tipo del campo
  • Restituisce void
  • Contiene i controlli di validità
  • Assegna con this.campo = parametro;

Capitolo 05

Perché usarli (davvero)

"Prof, ma se devo solo leggere e scrivere un valore, non faccio prima a renderlo pubblico?" — No. Ecco cinque buoni motivi.

🛡️ 1. Validazione dei dati

Il setter è il buttafuori all'ingresso: nessun dato incoerente entra nell'oggetto. Un prezzo negativo, una data di nascita nel futuro, una partita IVA di 5 cifre… tutto viene fermato.

🔒 2. Controllo degli accessi

Un campo può avere il getter ma non il setter. Così diventa di sola lettura dall'esterno: perfetto per un codiceCliente che non deve mai cambiare.

🔄 3. Manutenibilità

Se domani il campo eta deve diventare una LocalDate dataNascita, cambi solo l'interno della classe. Tutto il codice esterno che usa getEta() continua a funzionare.

🧮 4. Valori calcolati

Il getter può calcolare al volo: getEta() può derivare l'età da dataNascita. Il campo non esiste nemmeno, ma l'esterno non lo sa.

🏢 5. Standard riconosciuti dai framework

Spring, Hibernate, Jackson e tutti i principali strumenti Java leggono e scrivono oggetti solo attraverso i getter e i setter, seguendo le convenzioni JavaBeans. Una classe fatta bene è una classe che questi framework riescono a usare automaticamente.

Approfondimento: getter che calcolano

public class Dipendente {

    private String nome;
    private double stipendioLordo;

    public Dipendente(String nome, double stipendioLordo) {
        setNome(nome);
        setStipendioLordo(stipendioLordo);
    }

    public String getNome() { return nome; }
    public void setNome(String nome) { this.nome = nome; }

    public double getStipendioLordo() { return stipendioLordo; }

    public void setStipendioLordo(double lordo) {
        if (lordo < 0) {
            throw new IllegalArgumentException("Lo stipendio non può essere negativo");
        }
        this.stipendioLordo = lordo;
    }

    // Nessun campo "stipendioNetto": viene CALCOLATO al volo
    public double getStipendioNetto() {
        return stipendioLordo * 0.78;   // trattenute ~22%
    }
}

L'esterno chiama d.getStipendioNetto() come se fosse un campo normale. La logica di calcolo resta nascosta dentro la classe: se cambiano le aliquote, si modifica un solo punto.

Capitolo 06 — Novità

I record (Java 16+)

Quando una classe serve solo a trasportare dati immutabili, Java offre una scorciatoia: il record.

public record Punto(double x, double y) { }

Questa singola riga genera automaticamente:

  • i campi private final double x, y
  • il costruttore Punto(double x, double y)
  • i getter x() e y() — senza il prefisso get
  • equals(), hashCode() e toString() già pronti
Punto p = new Punto(3, 5);
System.out.println(p.x());        // 3
System.out.println(p);            // Punto[x=3.0, y=5.0]

// p.x() non ha setter: l'oggetto è immutabile.
// Se serve un punto diverso, se ne crea uno nuovo.
🧠
Quando usare cosa?
• Record → dati immutabili, "value object", DTO, coordinate, risposte di un'API.
• Classe con getter/setter → entità che devono cambiare nel tempo, con validazione e logica (un cliente che cambia indirizzo, un conto che cambia saldo).
📌
Nota per il programma: i record sono perfetti ma, se il tuo ambiente di sviluppo usa una versione di Java precedente alla 16, resta sui getter e setter classici. Nel dubbio, chiedi al docente quale JDK è installato.

Esercizi per casa

1 Classe Prodotto

Crea una classe Prodotto con i seguenti campi privati:

  • String codice — non modificabile dopo la creazione
  • String descrizione
  • double prezzo — deve essere sempre > 0
  • int quantita — deve essere sempre ≥ 0

Fornisci getter per tutti i campi e setter solo per descrizione, prezzo e quantità, con la validazione opportuna. Aggiungi un metodo getValoreTotale() che restituisce prezzo * quantita, e un toString().

Mostra la soluzione 
public class Prodotto {

    private final String codice;      // final: mai più modificabile
    private String descrizione;
    private double prezzo;
    private int quantita;

    public Prodotto(String codice, String descrizione, double prezzo, int quantita) {
        if (codice == null || codice.isBlank()) {
            throw new IllegalArgumentException("Il codice è obbligatorio");
        }
        this.codice = codice;
        setDescrizione(descrizione);
        setPrezzo(prezzo);
        setQuantita(quantita);
    }

    // Solo getter: il codice è di sola lettura
    public String getCodice() { return codice; }

    public String getDescrizione() { return descrizione; }

    public void setDescrizione(String descrizione) {
        if (descrizione == null || descrizione.isBlank()) {
            throw new IllegalArgumentException("La descrizione è obbligatoria");
        }
        this.descrizione = descrizione;
    }

    public double getPrezzo() { return prezzo; }

    public void setPrezzo(double prezzo) {
        if (prezzo <= 0) {
            throw new IllegalArgumentException("Il prezzo deve essere positivo");
        }
        this.prezzo = prezzo;
    }

    public int getQuantita() { return quantita; }

    public void setQuantita(int quantita) {
        if (quantita < 0) {
            throw new IllegalArgumentException("La quantità non può essere negativa");
        }
        this.quantita = quantita;
    }

    public double getValoreTotale() {
        return prezzo * quantita;
    }

    @Override
    public String toString() {
        return "Prodotto[" + codice + "] " + descrizione
             + " — € " + String.format("%.2f", prezzo)
             + " x " + quantita
             + " = € " + String.format("%.2f", getValoreTotale());
    }
}

2 Conto corrente

Crea una classe ContoCorrente con:

  • private final String iban
  • private String intestatario
  • private double saldo — solo getter, nessun setter pubblico

Il saldo deve poter cambiare solo attraverso i metodi versa(double importo) e preleva(double importo), che validano l'importo (positivo) e verificano la disponibilità. preleva restituisce true se l'operazione è andata a buon fine, false altrimenti.

Mostra la soluzione 
public class ContoCorrente {

    private final String iban;
    private String intestatario;
    private double saldo;

    public ContoCorrente(String iban, String intestatario, double saldoIniziale) {
        if (iban == null || iban.isBlank()) {
            throw new IllegalArgumentException("IBAN obbligatorio");
        }
        this.iban = iban;
        setIntestatario(intestatario);
        if (saldoIniziale < 0) {
            throw new IllegalArgumentException("Saldo iniziale non valido");
        }
        this.saldo = saldoIniziale;
    }

    public String getIban() { return iban; }

    public String getIntestatario() { return intestatario; }

    public void setIntestatario(String intestatario) {
        if (intestatario == null || intestatario.isBlank()) {
            throw new IllegalArgumentException("Intestatario obbligatorio");
        }
        this.intestatario = intestatario;
    }

    // SOLO getter per il saldo: nessun setter pubblico!
    public double getSaldo() { return saldo; }

    public void versa(double importo) {
        if (importo <= 0) {
            throw new IllegalArgumentException("L'importo deve essere positivo");
        }
        saldo += importo;
    }

    public boolean preleva(double importo) {
        if (importo <= 0) {
            throw new IllegalArgumentException("L'importo deve essere positivo");
        }
        if (importo > saldo) {
            return false;   // fondi insufficienti
        }
        saldo -= importo;
        return true;
    }

    @Override
    public String toString() {
        return "Conto " + iban + " (" + intestatario + ") — saldo € "
             + String.format("%.2f", saldo);
    }
}

3 Refactoring

Data questa classe scritta male, riscrivila applicando l'incapsulamento completo. Aggiungi la validazione: l'età deve essere tra 18 e 67, lo stipendio non negativo, il codice fiscale di esattamente 16 caratteri.

public class Dipendente {
    public String nome;
    public String codiceFiscale;
    public int eta;
    public double stipendio;
}
Mostra la soluzione 
public class Dipendente {

    private String nome;
    private final String codiceFiscale;
    private int eta;
    private double stipendio;

    public Dipendente(String nome, String codiceFiscale, int eta, double stipendio) {
        setNome(nome);

        if (codiceFiscale == null || codiceFiscale.trim().length() != 16) {
            throw new IllegalArgumentException(
                "Il codice fiscale deve avere 16 caratteri");
        }
        this.codiceFiscale = codiceFiscale.trim().toUpperCase();

        setEta(eta);
        setStipendio(stipendio);
    }

    public String getNome() { return nome; }

    public void setNome(String nome) {
        if (nome == null || nome.isBlank()) {
            throw new IllegalArgumentException("Il nome è obbligatorio");
        }
        this.nome = nome.trim();
    }

    // Codice fiscale: sola lettura
    public String getCodiceFiscale() { return codiceFiscale; }

    public int getEta() { return eta; }

    public void setEta(int eta) {
        if (eta < 18 || eta > 67) {
            throw new IllegalArgumentException(
                "Età fuori range (18-67): " + eta);
        }
        this.eta = eta;
    }

    public double getStipendio() { return stipendio; }

    public void setStipendio(double stipendio) {
        if (stipendio < 0) {
            throw new IllegalArgumentException("Stipendio non valido");
        }
        this.stipendio = stipendio;
    }

    @Override
    public String toString() {
        return nome + " (" + codiceFiscale + "), " + eta + " anni — € "
             + String.format("%.2f", stipendio);
    }
}
